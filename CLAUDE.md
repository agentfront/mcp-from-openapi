# CLAUDE.md - Project Guide for mcp-from-openapi

## Project Overview

**mcp-from-openapi** converts Swagger 2.0 and OpenAPI 3.0, 3.1 and 3.2 specifications into MCP (Model Context Protocol) tool definitions. It handles parameter resolution, schema conversion, security configuration, SSRF-safe `$ref` dereferencing, and format-to-schema enrichment.

## Architecture

```text
Swagger 2.0 / OpenAPI 3.0 / 3.1 / 3.2 Spec (JSON/YAML/URL/File)
    |
    v
OpenAPIToolGenerator (src/generator.ts)
    |-- constructor: the document's URIs (src/base-uri.ts): retrieval URI (documentUri | URL | file) + $self (3.2+)
    |-- initialize(): dereference $refs (self-references made local first, then $RefParser rooted at
    |                 the retrieval URI), then validate (once; rules of the declared version, a Swagger 2.0
    |                 document as written), then, Swagger 2.0 only, convert to OpenAPI 3.0 (once:
    |                 upgradeSwagger2, src/spec/upgrade-v2.ts; generation and lint read the conversion)
    |-- generateTools(): iterate paths, then operations via listOperations (src/spec/operations.ts)
    |-- generateTool(): build a single McpOpenAPITool
           |
           |-- ParameterResolver (src/parameter-resolver.ts)
           |      resolves params + requestBody into inputSchema + mapper
           |
           |-- ResponseBuilder (src/response-builder.ts)
           |      builds outputSchema from responses
           |
           |-- Format Resolution (src/format-resolver.ts)
           |      enriches schemas with format constraints (optional)
           |
           v
    McpOpenAPITool { name, description, inputSchema, outputSchema, mapper, metadata }
```

### Testing Patterns

- **Inline specs (unit tests)**: Unit tests create OpenAPI spec objects directly (no fixture files). E2E story tests MAY load vendored real-world fixtures from `e2e/fixtures/` — provenance, pinned commits, and licenses documented in `e2e/fixtures/README.md`; regenerating a fixture requires updating the literal count assertions that pin it
- **Real loopback servers**: URL-loading, SSRF/connection-pinning, and e2e wire tests drive a real
  `127.0.0.1` HTTP server (via the shared `src/__tests__/helpers/loopback.ts` helper, which also
  captures each request's method/url/headers/raw body for wire assertions) with
  `refResolution.allowInternalIPs`, exercising the actual Node pinned transport + SSRF guard.
  This replaces `global.fetch` mocks and `$RefParser.dereference` spies for those paths, because
  the pinned transport bypasses `global.fetch`. Use `jest.spyOn(Response.prototype, …)` for
  transport-error injection (SWC compiles named exports as non-configurable getters, so the
  module's own exports can't be `jest.spyOn`-ed).
- **Temp files**: File loading tests create temp files in `os.tmpdir()`, clean up in `finally`
- **Spy on dereference**: tests still spy on `$RefParser.dereference` to inspect the resolver
  _config_ (canRead/read/redirects) without network; the `read` path's actual fetch is validated
  against a real loopback server instead.
- **`c8 ignore next`**: Used for defensive branches unreachable through normal code paths (V8 coverage ignores)
- **`transformIgnorePatterns`**: `@apidevtools/json-schema-ref-parser` is ESM-only and must be transformed by SWC

### ESM Dependency Handling

`@apidevtools/json-schema-ref-parser` v16 is ESM-only. The project uses dynamic `import()` in `generator.ts` so it works from both CJS and ESM contexts. Jest transforms the package via `transformIgnorePatterns` in `jest.config.js`.

## Options Flow

```text
LoadOptions (factory methods; fromURL/fromFile pass the retrieval URI)
  -> fromURL/fromFile: parseDocumentUri(documentUri) FIRST [if set; before any request / file read]
  -> constructor (normalizes defaults)
      -> overlays applied EAGERLY, then detectSpecVersion (a Swagger 2.0 document: family `2.0`, `this.swagger`)
      -> resolveDocumentBase(document, version, retrievalUri | documentUri)
         -> identities (retrieval URI + $self) and the retrieval base (retrieval URI; $self only without one)
  -> initialize()
      -> prepare(): JSON copy + findSelfReferences() made local [if the document has a URI]
      -> dereferenceInternal() [no external ref left: self-references included, also under secureDefaults]
         or $RefParser.dereference(root = retrieval base, copy) [external refs; root omitted without a base]
         [if dereference: true]
      -> Validator.validate() [if validate: true; a Swagger 2.0 document is validated as written]
      -> Swagger 2.0 only: upgradeSwagger2(dereferenced, { documentUri: retrieval URI }) once -> upgradedDocument
         [always, also with validate: false; dereference: false is refused first (DEREFERENCE_REQUIRED)]

generator.validate() -> the same dereference first when a `$ref` not starting with `#` exists
                        (dereference: true); an unreadable reference -> { valid: false, UNREADABLE_REFERENCE }
                        Swagger 2.0 + dereference: false -> { valid: false, DEREFERENCE_REQUIRED }
                        (validate() reads the 2.0 document as written, never the conversion)

GenerateOptions (generateTools/generateTool)
  -> ParameterResolver(namingStrategy)
      .resolve(operation, pathParams, security, includeSecurityInInput)
  -> ResponseBuilder(preferredStatusCodes, includeAllResponses)
      .build(responses)   [explicit preferred code > explicit 2xx > range covering a preferred code or 2XX > 3xx > first]
  -> resolveSchemaFormats(schema, resolvers) [if resolveFormats/formatResolvers set]
```

## Key Conventions

- `toJsonSchema()` converts OpenAPI SchemaObject to JSON Schema 2020-12 (exclusiveMin/Max boolean-to-numeric, `nullable` → type union, `example` → `examples`, drops `xml`, boolean schemas and three Swagger 2.0 spellings: see below)
- Schemas pass through `toJsonSchema()` in both ParameterResolver and ResponseBuilder
- Metadata is attached via `x-` prefixed properties (`x-parameter-location`, `x-parameter-style`, `x-parameter-explode`, `x-parameter-content-type` for a `content` parameter, `x-parameter-whole-query` for `in: querystring`, `x-status-code`, `x-content-type`)
- The `mapper` array maps inputSchema keys to their HTTP locations (path/query/header/body/cookie); `wholeBody: true` means the value IS the entire body and `wholeQuery: true` (a `type: 'query'` entry, OpenAPI 3.2 `in: querystring`) that the value IS the entire query string; `serialization.binary` marks file parts
- A parameter defined with `content` (any version, any location) takes its input schema from the media type's schema (no schema: `{}` for a JSON media type, `{ type: 'object' }` for `application/x-www-form-urlencoded`, `{ type: 'string' }` otherwise — `classifyMediaType` in `src/media-type.ts`, the classification `buildHttpRequest` serializes by); its mapper entry has `serialization: { contentType, encoding? }` and NO `style`/`explode`/`allowReserved`; `buildHttpRequest` serializes it by media type (JSON text, form string, or the primitive itself; a form string applies the media type's `encoding`) before the location's own escaping. `schema` wins when a parameter has both, except `in: querystring`, which is defined by `content` alone. Several media types: `selectRequestMediaType` picks one + `INVALID_PARAMETER_CONTENT`
- Parameter merge (`analyzeParameters`, the ONLY implementation: generator, validator and lint all call it, never re-merge): an operation-level parameter OVERRIDES a path-level one with the same `name` + `in` (silent; a HEADER name compares case-insensitively and the operation's spelling is kept, query/cookie names stay exact); the last of a repeated `name` + `in` within one list wins (`DUPLICATE_PARAMETER`). The conflict rule (same name in DIFFERENT locations -> `conflictResolver` rename) is unchanged; a renamed key or a security input key that another input already uses gets a number (`uniqueKey`), so every input key names one value, and a scheme named in several requirements is one entry. `ParameterResolver.resolve` leaves out (its `ignored` list, the generator's `PARAMETER_IGNORED` warning) a header parameter in `IGNORED_HEADER_PARAMETERS` or `X-Forwarded-*` (OpenAPI's `Accept`/`Content-Type`/`Authorization`, framing, routing and method-override headers) and a parameter sent where a credential of the operation is sent (`wireName`: location + name, a header name in any case) The querystring rules (at most one, never with `in: query`, needs `content`) are checked on the merged list by the validator (errors) and by the generator under `validate: false` (operation skipped, same codes)
- Parameter `name` (`readParameterName`, `src/spec/parameters.ts`, shared by validator, generator and converter): a string is used as is; a NUMBER or BOOLEAN (YAML reads an unquoted `2024`/`true` so) is read as its text with a `PARAMETER_NAME_NOT_STRING` warning, in every version; absent, `null`, `''`, an object or an array is no name: a validation error (`MISSING_PARAMETER_NAME` for absent/`null`/`''`, `INVALID_PARAMETER_NAME` for an object or array) and, under `validate: false`, the operation is skipped with `INVALID_PARAMETER_NAME`. Never `String()` an object name
- Security info lives on mapper entries (not on inputSchema unless `includeSecurityInInput: true`)
- Tool names are always normalized to MCP rules (`[A-Za-z0-9_.-]`, `maxToolNameLength` cap default 64, hash-suffix truncation, collision dedup in `generateTools`)
- OpenAPI types (`src/spec/types`) are reader types: they describe documents we read, so the validator rejects invalid documents and the compiler does not. They declare no index signatures (an index signature rejects a document typed with the caller's own interfaces); `x-` extensions are read through `WithExtensions`
- Enumerated strings in the OpenAPI types are open (`'query' | 'header' | (string & {})`) wherever the field is a plain string; a spec map (paths, responses, `content`, components) is `SpecMap<T>` = `Record<string, T | undefined>`; free-form values (`example`, `default`, `enum`/`const` members) are `FreeFormValue` = `any` by design
- `SchemaObject` is always the object form; a boolean schema is typed only through `SchemaOrBoolean`. The cross-version aliases keep their names and stay assignable in both directions with the last published release, apart from the allowlisted differences
- Generation follows features, with ONE exception: operation discovery follows the declared version. `query` and `additionalOperations` are read only when the document declares 3.2 or newer (a newer 3.x minor included); in 3.0/3.1 each is ignored with one `FEATURE_NEWER_THAN_DECLARED_VERSION` diagnostic, and a missing/malformed/unsupported version (reachable only with `validate: false`) reads the eight historical methods. This is decided in exactly one place, `resolveOperationLayout(detectSpecVersion(document))` (exported), used by the generator, validator, lint and Arazzo, so an `excludeMethods` list written for the old methods cannot be bypassed by a new method. Everything else (parameter locations, bodies, security, schemas) is processed whatever the document declares; `in: querystring` is read in every version (a 3.0/3.1 document only gets the `FEATURE_NEWER_THAN_DECLARED_VERSION` warning). The validator applies the profile of the declared `major.minor` (the patch never matters)
- Swagger 2.0 is CONVERTED, not read by a second generator: overlays -> dereference (`dereference: false` is refused: `DEREFERENCE_REQUIRED` is returned by `validate()`, thrown as a `ParseError` by generation and `lint()` even with `validate: false`, and never a `getDiagnostics()` entry) -> validate with the 2.0 profile AS WRITTEN (`validate()` never sees the conversion) -> `upgradeSwagger2` once -> generate from the conversion. `getDocument()` has three states (as loaded; dereferenced 2.0, after `validate()` of a document with external references; converted `3.0.3`, after generation or `lint()`), `getSpecVersion()` says `2.0` in all of them. Every diagnostic with a `path` points into the 2.0 document as written (`SpecDiagnostic.document: 'source'`, set by `addDiagnostic`; `'converted'` is only for a construct the conversion alone has and is not used today): converter findings (`SWAGGER_*`, and `FEATURE_NEWER_THAN_DECLARED_VERSION` for `trace`/`query`/`additionalOperations`) and, through the converter's `parameterIndexes`, generation findings about a parameter, which name its index in the 2.0 `parameters` list, so one finding is recorded once (`DUPLICATE_PARAMETER`); body-conflict findings point at `<operation>/parameters`. The converter groups what it finds (one diagnostic per kind, `(in N places: ...)`). A document without `host` takes host and scheme from an http(s) retrieval URI (`fromURL`, `documentUri`), else its server is the relative `basePath` (`SWAGGER_RELATIVE_SERVER_URL`; the validator's `NO_SERVERS` cannot know the URI); only `http`/`https` schemes (any case) make servers, `ws`/`wss` make none; `basePath` must start with `/` and be URL-safe (`INVALID_BASE_PATH`; under `validate: false` a missing `/` is added and an unusable path dropped, each warned). Security: `components.securitySchemes` is kept whenever the source has `securityDefinitions`, so an operation requiring a scheme that could not be converted (unknown `type` or `flow`) is skipped with `UNSATISFIABLE_SECURITY`, whether or not other schemes exist. Forms: a form with a `type: file` field is multipart only; array fields carry `collectionFormat` as per-field `encoding` in urlencoded AND multipart bodies. Every `in: path` parameter converts as required. Limits (a 2.0 `consumes`/`produces`/path-level parameter applies to every operation, so the 3.0 form repeats it): 32 media types per list (`SWAGGER_MEDIA_TYPE_LIMIT`) and `MAX_CONVERSION_ENTRIES` created entries, past which generation, `generateTool()` and `lint()` throw a `ParseError` whose context carries `SWAGGER_CONVERSION_TOO_LARGE`. The converter is total (it never throws), pure and linear; a rule only generation needs does not belong in it, and a rule that depends on the version belongs in `SPEC_PROFILES`
- Boolean schemas (JSON Schema 2020-12; OpenAPI 3.1 and 3.2): `toJsonSchema` makes `true` `{}` and `false` `{ not: {} }` wherever it converts a subschema (`properties`, `prefixItems`, `allOf`/`anyOf`/`oneOf`, `$defs`, `definitions`, `patternProperties`, `dependentSchemas`, `items: true`, `not: true`, the root), so later steps only meet objects; a boolean that is a keyword's own value stays (`additionalProperties`, `items: false`, `not: false`, `contains`, `propertyNames`, `if`/`then`/`else`, `contentSchema`, `unevaluated*`). `isPresentSchema` (truthy or `false`) decides whether a media type's or parameter's `schema` counts: a request body `schema: true` is a whole body `{}`, `false` a REQUIRED whole body `{ not: {} }` (no call can satisfy it), a parameter `schema: false` is an input `{ not: {} }`, a response `schema: false` has an `outputSchema`. Client targets recognise "never" (`isNeverSchema`: `{ not: {} }` or `{ not: true }`): `openai` drops an optional never property from a closed object (elsewhere it stays optional, and a required one stays required), `gemini` keeps the first variant that accepts a value (a nullable wrapper whose other member is never is not unwrapped, since that would reject `null` too: gemini gives `{ type: 'null' }`, the other targets' root collapse the `x-variants` node)
- `x-status-code` is a number (an explicit code, `0` for `default`) or a range string (`ResponseStatusRange`: `1XX`..`5XX`, any case in the document, upper-case in the output); `metadata.responseStatusCodes` holds the numbers, `metadata.responseStatusRanges` the ranges (absent when none) and `ResponseStreamInfo.statusCode` is either. The preferred response (`includeAllResponses: false`, and streams) is the first rule that finds a candidate (`selectPreferredResponse`): an explicit code in `preferredStatusCodes` in its order; any explicit 2xx; a range covering a code of `preferredStatusCodes` in its order, else `2XX`; an explicit 3xx, else `3XX`; the first. An explicit code beats a range of its class only for a code listed in `preferredStatusCodes` (rule 1), for 2xx (rule 2, before every range rule: `{ 299, 2XX }` gives 299) and for 3xx while no range covers a preferred code (`{ 399, 3XX }` gives 399, but 3XX with `preferredStatusCodes: [301]`); in 1xx/4xx/5xx a range covering a preferred code wins (`{ 499, 4XX }` with `[404]` gives `4XX`, the default list gives 499); a key `parseInt` reads (`200`, `404`) is still a number. `default` only when nothing else has a schema
- Three tolerant Swagger 2.0 normalisations run in `toJsonSchema` whatever version the document declares (real 3.x documents carry them): `x-nullable: <boolean>` stands for `nullable` when the schema has no `nullable` (and is dropped), `type: file` (or `file` in a `type` list) is `type: string, format: binary`, a string `discriminator` is `{ propertyName }`. The converter applies the same three to a 2.0 document (its own `SchemaRewriter`), so neither path leaves a string `discriminator` or `type: file` behind

- Operations are enumerated ONLY through `listOperations` / `getOperation` (`src/spec/operations.ts`) with the document's layout, never by indexing a path item with a method name: one list of methods, own-property reads (no `constructor` from the prototype), a diagnostic for what is ignored. Standard methods match in any case; an additional method matches EXACTLY as written everywhere (`getOperation`, `generateTool`, Arazzo `operationPath`, `includeMethods`) except `excludeMethods`, which matches it in any case (`matchesMethodFilter`), so a document cannot pass an exclusion by spelling `PURGE` as `Purge`
- `metadata.method` is the lowercase fixed field name (`get`, `query`) or the `additionalOperations` key exactly as written (`LINK`); `HTTPMethod` is `StandardMethod | (string & {})`. Dedup hashes and names are seeded with it, so never upper-case it before storing; only `wireMethod` (used by `buildHttpRequest`) upper-cases a standard method
- An operation `generateTools` cannot build leaves `TOOL_GENERATION_FAILED` (besides the old `console.warn`); with `dereference: true`, a parameter, request body or security scheme still a Reference Object after dereferencing (an external one `secureDefaults` did not read) skips the operation with `UNRESOLVED_REFERENCE` (a scheme: `UNRESOLVED_SECURITY_SCHEME`), a response is ignored with it; `dereference: false` keeps reading Reference Objects as before. A document that is not an object (`null`, an empty YAML text) is a `ParseError` at load; `generateTool` throws `GenerationError` for a missing operation; a `tags` value that is not a list counts as no tags. The internal dereferencer shares one placeholder per TARGET (every spelling of a pointer, `#//a`, `#a/`, gets the same object), `findRelativeReference` walks with parent links (`PathVisit`, `locationOf`, shared with `findSelfReferences`), and `parseDocumentUri` checks the length of the normalized `href` too
- Diagnostics instead of silent drops: a construct that is skipped or ignored (an unresolved security scheme, an unmapped parameter location, an ignored operation key) is recorded via `generator.getDiagnostics()` (`{ severity, code, message, path, document? }`, `path` a JSON Pointer, `document` only for Swagger 2.0) and never dropped without a trace. Every code is in `DIAGNOSTIC_CODES` (`src/types.ts`; the spec layer's subset is `SPEC_DIAGNOSTIC_CODES`). The list is de-duplicated with `diagnosticKey` (bounded, so a huge document cannot make the key huge) and capped at `MAX_DIAGNOSTICS` (1,000) with a WARNINGS-FIRST policy: when full, a new warning takes the place of the most recently recorded `info` (while there is one) and a new `info` is not recorded; the one final `DIAGNOSTICS_TRUNCATED` counts dropped warnings and infos separately (a finding dropped and found again counts once, bounded by `MAX_DROPPED_KEYS`). The validator caps `errors`/`warnings` at the first 1,000 each, then its own `DIAGNOSTICS_TRUNCATED`. Validation errors still throw `ParseError` (message names the first error, bounded and escaped; `context.errors` lists all); only warnings and skips are diagnostics
- Untrusted document text never goes raw into a message or a path: `describeValue` (`messageText` in the validator) for values quoted in messages, `jsonPointer`/`appendPointer` for `path`. They cut long text and write control, bidirectional and lone-surrogate characters as `\uXXXX`; a pointer with a cut or escaped segment is display-only. The validator's legacy codes keep their historical unescaped `path` (key cut at `LEGACY_PATH_KEY_MAX_LENGTH`)
- A Security Requirement key that is not a component name is, in a document declaring 3.2+, read as a URI reference (`findSecurityScheme` -> `resolveSecuritySchemeUri`): it names a scheme when it resolves to THIS document with the fragment `/components/securitySchemes/<name>` (a component name always wins; `./foo` is never the component `foo`; a fragment-only key works without a base URI). A scheme of another document is never fetched. A Security Requirement object naming an undefined scheme is dropped as a whole (`UNRESOLVED_SECURITY_SCHEME` per missing scheme), and so is one naming a scheme the library cannot send (`UNSUPPORTED_SECURITY_SCHEME`: `securitySchemeProblem` with the latest profile's `securitySchemeTypes`/`apiKeyLocations`, exact values, `name` required; the validator applies the declared version's as `INVALID_SECURITY_SCHEME`; `mutualTLS` keeps its tool with an `info`); when every requirement of an operation is dropped the tool is not generated (`UNSATISFIABLE_SECURITY`, `generateTool` throws `GenerationError`), unless the document defines no schemes map at all (no `components.securitySchemes`; Swagger 2.0: no `securityDefinitions`), which keeps generating with empty security (an empty map counts as defined)
- Tool `title`/`annotations` come from HTTP-method inference (`inferAnnotations`, default on) + `x-mcp` family overrides in `src/annotations.ts`
- `generateTools()` output is deterministically ordered (path asc, canonical method order)
- Filtering: tags/methods/path globs/`readOnlyOnly` in `shouldIncludeOperation`; `x-mcp` enable/disable resolves root < path < operation. Path globs match the path key with unreserved percent-escapes decoded (`normalizeEscapes`, `/%61dmin` is `/admin`), by `matchesGlob`, which follows every glob position at once (time glob x path, never a backtracking regex). `readOnlyOnly` keeps safe methods only (`inferAnnotationsFromMethod`); an extension's `readOnlyHint: false` takes one out, `true` never puts another method in. `includeOperations` is an allow-list: an operation without a string `operationId` is never in it; the validator warns about a repeated `operationId` (`DUPLICATE_OPERATION_ID`, JSON Pointer path). Scopes of one scheme named twice in a Security Requirement are merged through a `Set`
- `buildHttpRequest` is the canonical request assembly (pure, no fetch); `RequestBuildError` for all failures. The resolved path must start with exactly one `/` (never `//host`, `/\host`, or a path glued onto the base's authority, whatever the base, relative mode included) and may hold no `.` / `..` segment (literal or `%2e`) and no empty segment where its template has a non-empty one (an empty path value, a label style composing `..`); a trailing slash the template has is kept (`assertPathNamesTemplateResource`). The validator refuses the same in path keys: a backslash, an empty inner segment (`//`), a dot segment, a `{` or `}` outside a `{name}` expression (`INVALID_PATH_FORMAT`, `pathTemplateProblem`) `url` is authoritative: a non-form whole query is ONE serialized value, exposed as `queryString` with `query` `{}`, so it must never be re-parsed or re-encoded as pairs (`URLSearchParams`). Input values are read with `Object.hasOwn` (an inherited `toString` is never a value) and `headers`/`query`/`cookies` are built on prototype-free records, then copied to ordinary objects, so any parameter name is an own key. Cookies without `style: cookie` keep their old output (arrays comma-joined, commas tolerated); `style: cookie` and `content` cookies follow RFC 6265 exactly. RESERVED NAMES: a name the INPUT chooses (property of a form whole query, of an exploded form object in the query, a `deepObject` bracket name in the query or in a form/multipart field, of an exploded `style: cookie` object) is refused when another mapper entry in the same location uses it (a credential, supplied or not, or a sibling parameter), also as the part before its first `[` (`api_key[]`) and, for a credential, in any case (`API_KEY`), so a caller-controlled value can never add or replace a credential; cookie objects may not name one cookie twice. Form serializers (body, whole query, `content`) omit `null` properties (JSON bodies keep it; multipart sends `null` as text for a field with no Encoding Object and omits it for one with). ENCODING OBJECTS are applied per field in form bodies, form whole queries, form `content` parameters and multipart bodies: `style`/`explode`/`allowReserved` serialize like a query parameter with the same values (`serializeQueryPairs`; `contentType` is ignored when any is set, as 3.2 says; `deepObject` nests brackets and refuses an array of objects), otherwise the field is written by `contentType` (`contentText`); multipart part `headers` are sent only when their schema fixes one value; a multipart body is `FormData`, or a `Blob` written by the builder (with `content-type` + boundary in `headers`) when a part needs a `Content-Type` or header; names an Encoding Object puts on the wire (exploded properties, `meta[a]`) fall under RESERVED NAMES; without `encoding` the output is unchanged. `allowReserved` (`keepReserved`): `: / ? @ ! $ ' ( ) * , ;` stay raw and a valid `%XX` passes, `& = + # [ ]` are ALWAYS encoded and any other `%` is `%25`, so an input value can never add a query pair or end the query; no effect on a path, header, cookie, `content` parameter or non-form whole query. Header values: only tab, space, visible ASCII, U+0080-U+00FF (JSON `content` headers escape non-ASCII as `\uXXXX`); a lone surrogate is refused by every percent- and form-encoder; a whole-query entry without a media type fails whatever the input
- `target` client-dialect transforms run LAST in generateTool (after formats and depth truncation)
- `secureDefaults: true` = redirects off + external refs off (explicit options still win); a `$ref` to the document's own URI is not external (see self-reference rewriting), so it still resolves; any other external ref stays as written in the output, with no error
- Identity vs retrieval (`src/base-uri.ts`): a document has IDENTITY (the URIs that name it: its retrieval URI and, from 3.2, `$self` resolved against the retrieval URI; used for self-references and security scheme URIs, a relative reference counts when it resolves to one against either) and a RETRIEVAL BASE (what relative references to other documents are READ against). The retrieval base is the retrieval URI whenever one is known: `fromURL` = the final URL after redirects without userinfo/fragment, `fromFile` = `pathToFileURL`, `LoadOptions.documentUri` overrides both. `$self` is the retrieval base ONLY for `fromJSON`/`fromYAML` without `documentUri` and only when absolute; with neither, relative refs resolve against the working directory as before and `ExternalRefError` adds a hint. The specification takes `$self` as the base for both; where to retrieve from is left to implementations, so identity follows the spec and the retrieval location is an implementation choice: a file-loaded spec reads its siblings whatever `$self` says, a mirror serves its own copies. `documentUri` is validated BEFORE any request or file read (`fromURL`/`fromFile` call `parseDocumentUri` first). Every URI used (`documentUri`, `$self`, the retrieval URI) is at most 2,048 characters (`MAX_BASE_URI_LENGTH`): a longer retrieval URI is not used (`BASE_URI_TOO_LONG`; relative refs then fail with rule `base-too-long`, never against the working directory). The base only changes how a relative ref becomes an absolute URL: that URL then passes the SAME allow-list / host gate / `safeFetch` pinned transport as an absolute `$ref`, and `LoadOptions.headers` are never sent to a `$ref`. No kept URI carries userinfo. `$RefParser` applies a nested `$id` base only to documents declaring 3.1
- Self-reference rewriting (`prepare`): the copy of the document is scanned by `findSelfReferences`; each `$ref` naming the document (compared by `uriComparisonKey`: scheme/host/port/path/query, fragment dropped, default port and dot segments removed by the URL parser, unreserved percent-escapes decoded and hex upper-cased, `%2F` != `/`, empty `?` != no query, userinfo distinguishes) becomes its local `#...` form BEFORE `hasExternalRefs` decides the path, so no fetch happens, also under `secureDefaults`. The fragment is percent-decoded as a JSON Pointer; no fragment / `#` / `""` (with a base) = the whole document; the target must exist as written (own properties) and the pointer may not pass through another `$ref`, else `ParseError` rule `missing-target` (never `{}`); siblings are dropped like for `#/...`. Plain-name fragments (`#Pet`) are left to `$RefParser`, nothing under a schema with its own `$id` (any version), nothing without a URI. Ordinary local `#/...` refs keep the old reading (no decoding, `{}` for a missing pointer)
- `$self` rules (`resolveDocumentBase`): read only in documents declaring 3.2+ (newer minors included); ignored with a diagnostic, never an error from the generator: not read in 3.0/3.1 (`FEATURE_NEWER_THAN_DECLARED_VERSION`), `INVALID_SELF` (not a string / not RFC 3986 characters / fragment; the validator rejects it too), `REFUSED_SELF` (userinfo, scheme other than http/https/file, `file:` with a host, `file:` in a document retrieved over http(s), longer than 2,048 or resolving to a longer URI), `UNRESOLVABLE_SELF` (relative with no usable retrieval URI). `$self` is not a trust origin: it adds NO reach beyond an absolute `$ref` (every URL built from it passes the same gates), never affects `servers`, and only the root document's is read. Changes in default reach caused by having a base: `fromURL` relative refs are fetched from the document's location (they used to fail), and a document with no retrieval URI and an absolute http(s) `$self` fetches its relative refs from it. A file-loaded spec with a network `$self` still reads files (the `$self` is identity only). With `file` allowed, a document fetched from the network can still read local files through an absolute `file:` ref (predates the base URI; `docs/ssrf-prevention.md` Trust Model)
- `validate()` dereferences: with `dereference: true`, when the document holds a `$ref` not starting with `#` (a self-reference included), `validate()` runs the dereference (`initialize(false)`: one shared promise, at most once per generator, reused by generation and the reverse, retried after a failure) and validates the DEREFERENCED document; otherwise it validates the loaded one. An unreadable reference does NOT throw: the result is `{ valid: false, errors: [{ code: 'UNREADABLE_REFERENCE', message, path? }] }` (`message` = the `ParseError` message without `DEREFERENCE_ERROR_PREFIX`; any `ParseError` with a `context.rule` is converted). A document `JSON.stringify` cannot copy (a YAML alias cycle) still throws. It records no diagnostics. `UNREADABLE_REFERENCE` is in `DIAGNOSTIC_CODES` but is never a `getDiagnostics()` entry
- Refused refs: the `refused` resolver (order 1) takes exactly the references neither the file resolver (when `file` is allowed) nor `canReadHttp` takes; the file `read` is `readLocalFile` (the path `$RefParser` would read, opened with `O_NONBLOCK` and checked on the open handle: only a regular file of at most `DEFAULT_MAX_RESPONSE_BYTES`, 10 MiB, `too-large` past it; a device, pipe or directory is `file-error`, as is a `file:` URL naming a host); the file and http `read`s and `refused` all throw an `ExternalRefError` carrying a `RefRule` (`protocol`, `host-not-allowed`, `host-blocked`, `internal-address`, `resolved-address`, `dns-failed`, `too-large`, `timeout`, `response`, `fetch-failed`, `file-error`, `too-many-documents`; `fetchFailure` maps an `SsrfError.context.reason` through `SSRF_REASON_RULES`). `prepare` throws one for `missing-target` and `base-too-long`. Every read goes through `orderedReads`, so the failure reported is the first in DOCUMENT order whatever order the network answers in, and reads asked after a failure are not started. Reads are bounded: at most `MAX_CONCURRENT_READS` (8) run at once, a dereference reads at most `refResolution.maxDocuments` documents (default 10,000, rule `too-many-documents`) holding at most `refResolution.maxTotalBytes` (default 100 MiB, rule `too-large`) and runs at most 10 × `LoadOptions.timeout` (rule `timeout`); a reached limit stops starting reads (`admit` / `account`, applied by `withinLimits` to file and http reads alike; `positiveOr` reads a non-positive value as the default). `orderedReads` returns `{ read, settle, admit, account }`: `initialize` calls `settle()` in its `catch` before throwing, for ANY failure (also a document `$RefParser` cannot parse, which fails no read), so no read is started after it and the rejection settles only after every read already started has ended: a rejected `initialize()` leaves no request or file read running, and a failure can wait up to `LoadOptions.timeout` for a slow read already in flight `dereferenceError` finds it in the `cause` chain and builds the `ParseError`; message AND `context` (`rule`, `reference`, `base`, `resolved`, `path`) are cut at 256 chars and escaped; in `reference`/`base`/`resolved` a query is `?...`, user information `***` (also as `asUrlPath` writes it, where resolving moved it into a path) and the working directory `<working directory>/` (`workingDirectoryForms`); the raw error NOT kept. Other failures get `invalid-document` (`ParserError`), `missing-target` (a pointer error) or `unreadable`, with only `rule`. `fromArazzo` rejects `loadOptions.documentUri` (`ArazzoError`: one URI would name every source)
- `LoadOptions.overlays` apply BEFORE dereference/validation, exactly once; `generator.lint()` runs on the patched document. Each target gets its own JSON copy of an action's `update` (never the overlay's object), so a later action changing one target cannot reach the others, and the caller's overlay is never modified
- Trimming order in generateTool: formats → depth truncation → stripExamples/maxProperties/maxDescriptionLength → client target
- `metadata.responseHints` (unboundedArray/paginationParams/largeResponseRisk) computed on the FINAL output schema; `streaming` is set whenever `metadata.responseStream` is
- A streamed response (OpenAPI 3.2 `itemSchema`) is `metadata.responseStream = { statusCode, contentType, itemSchema }`, NEVER an array/stream `outputSchema`. Selection: the response by `preferredStatusCodes` (the order below), then within it the FIRST media type in document order that declares `itemSchema` (no preference list; independent of the media type `outputSchema` is read from, so JSON + `text/event-stream` gives both): an MCP tool that declares an output schema must return structured content, which an unbounded stream cannot. A media type with only `itemSchema` adds nothing to `outputSchema`; `itemSchema` goes through the same formats/depth/trim/target steps as an output schema. A request body with only `itemSchema` -> `UNSUPPORTED_STREAMING_REQUEST_BODY`, no body input
- Format resolution is a post-processing step applied to final inputSchema/outputSchema; `maxSchemaDepth` truncation (default 10) runs after it, BEFORE client target transforms
- Shared `$ref` targets stay bounded (issue #48): `toJsonSchema` converts each acyclic node once and stops at `maxDepth`; a revisited result is reused if its conversion was self-contained (no depth cut, no cycle back to it or above), else only if Tarjan SCC — run lazily, at most once per conversion, over the edges walkable within `maxDepth` — shows it off any walkable cycle (cyclic nodes convert per path, preserving the cut-at-revisit output) (`allOf` members don't count — body flattening hoists them) with `{}` placeholders that `truncateDepth` always discards. `resolveSchemaFormats` memoizes by node; `truncateDepth` materializes a fresh unshared tree. `maxSchemaNodes` (default 25,000, `DEFAULT_MAX_SCHEMA_NODES`; it was 100k when a schema over it cost the tool) budgets every conversion visit (converted, reused, or placeholder — each fills a slot) and the truncated output → `SchemaError` (`ArazzoError` from `fromArazzo`); in `buildTool` a node-budget failure of the input, output or stream item schema (conversion or truncation, `isNodeBudgetError`: `context.maxNodes`) does not fail the tool: `fitSchemaDepth` builds that schema again at the deepest depth that fits (bisection below `maxSchemaDepth`; a shallower cut never needs more nodes), re-running only the truncation when the conversion at `maxSchemaDepth` fitted (`fitSchemaDepth` and `isNodeBudgetError` live in `src/schema-builder.ts`, shared with Arazzo) (that conversion and its resolved formats serve any smaller depth: the output is the same as converting at the smaller depth), and records `SCHEMA_DEPTH_REDUCED` once the tool is made, at the end of `buildTool` (path: the operation for the input, `<operation>/responses` for the others); only when not even depth 1 fits is it a `SchemaError` (`... even cut at depth 1 ...`, `context`: `maxNodes`, `maxSchemaDepth`, `schema`). The other budgets (values copied into the tool, client-target inlining, extension meta) still fail the tool; `ResponseBuilder` picks the emitted responses before converting, so unselected ones cost nothing. Generator output is byte-identical to per-occurrence conversion; conversion and truncation must use the same `resolveSchemaLimits` depth
- Walks over unbounded nesting keep explicit stacks (issue #50): `dereferenceInternal`, `toJsonSchema` (frames with child slots, visited in the recursive order so cache/budget behave identically), body flattening (`collectObjectMembers`), `resolveSchemaFormats`, lint's `measureSchema`/`schemaHasExample`, and x-mcp `cleanseMeta` walk with explicit stacks, so `$ref` chains of any length generate. `truncateDepth` and every later step recurse per level, bounded by `maxSchemaDepth`; `generateTool` turns a stack overflow there into a `SchemaError` naming `maxSchemaDepth`
- Budgets above one schema: all conversions of one tool schema (every parameter of the input, every response of the output) also share `SchemaConversionOptions.sharedBudget` = 4 × `maxSchemaNodes` (`SHARED_CONVERSION_BUDGET_FACTOR`), so an operation with thousands of parameters referencing one schema fails or is cut shallower instead of converting each in full (it used to exhaust memory); `GenerateOptions.maxTotalSchemaNodes` bounds the JSON values of all tools of one `generateTools()` run (or one `generateTool()`; input + output + stream item schemas, counted only when finite), `SchemaError` with `context.maxTotalSchemaNodes`, rethrown past the per-tool catch (`runFailures`); unlimited by default, `SECURE_MAX_TOTAL_SCHEMA_NODES` (10,000,000) under `secureDefaults` (`resolveMaxTotalSchemaNodes`). Stripe holds 4.5M, GitHub 0.65M, Microsoft Graph 80M. Option values of the wrong type fall back: a non-number `maxSchemaNodes` is the default (`resolveSchemaLimits`), a `maxToolNameLength` that is not a positive number is 64 (`positiveOr`, also used for `refResolution.maxDocuments` and `maxTotalBytes`)
- `maxSchemaNodes` counts every JSON value (issue #50): `truncateDepth` charges each schema object, keyword value, and value inside it; conversion charges 1 per visit plus 1 per keyword of each converted schema (a cyclic schema converts once per path; a boolean `false` becomes `{ not: {} }` and so costs 2, the schema and its `not` keyword, like any one-keyword schema; `true` is `{}`); client-target `inlineLocalRefs` takes `{ maxNodes }` (generator passes `maxSchemaNodes`; standalone unbounded), caps nesting incl. `$ref` hops at 1000, and neither copies nor charges target keywords a `$ref`'s siblings overwrite (`undefined` placeholders keep key order). Every budgeted walk counts an array hole as the `null` it serializes as, rejecting an array longer than the budget left before walking it (`ensureBudget`/`mapSlots`, conversion's `queueMembers`). Smallest budget for every real tool: 22,232 (full GitHub spec), 19,225 (Discord)
- Documents are trees before the first copy: YAML goes through `parseYamlText` (alias count, then expansion), `fromJSON` and `fromArazzo` objects through `assertBoundedExpansion`, so an alias graph or a shared object graph that a `JSON.parse(JSON.stringify())` copy would expand exponentially is a `ParseError` (`LoadError` from `fromURL`/`fromFile`, `ArazzoError` from `fromArazzo`), never an out-of-memory abort; `validate()` would not see it (it is valid)
- Spec values that land in a tool are copied, never shared (`copyJsonValue`): dereferencing resolves `$ref`s inside values too, so a few can expand exponentially. EXCEPT a schema's specification extensions: a `$ref` inside an `x-` value is no Reference Object in any version, so both dereferencers record where they replaced a `$ref` and by what (`src/reference-sites.ts`) and a tool's schemas get each such `$ref` back (`{ $ref: <text the dereferencer read> }`, two nodes: relative to its file, a self-reference in local form, siblings dropped) instead of the resolved graph (Stripe's `x-expansionResources`), while the value put there is still there; `getDocument()`, `default`/examples values and `x-mcp`/`x-frontmcp` meta still hold the resolved values. `fromArazzo` cuts a workflow's input and output schemas shallower the same way (`fitSchemaDepth`; an output returning `$inputs.x` is derived from the inputs converted at each depth tried) and reports through `FromArazzoOptions.onDiagnostic(diagnostic, source?)`: its `SCHEMA_DEPTH_REDUCED` findings, then every diagnostic of the generators it created for raw sources, once every tool is made `truncateDepth` copies every object-valued keyword (`default`, `examples`, `enum`, `required`, `x-*`, ...) and counts its values against `maxNodes`; `buildTool` copies `title`, `mapper`, `metadata`, and `_meta`'s operation entry under a `maxSchemaNodes` budget; extension `meta` is copied with prototype keys omitted, every value of `x-mcp` + `x-frontmcp` meta counting against `maxSchemaNodes` (`extractExtensionOverrides(op, { maxMetaNodes })`, default 25,000 = `DEFAULT_MAX_SCHEMA_NODES`). Cycles are dropped; nesting past 1000 levels → `SchemaError`. Operation filters (`resolveExtensionEnabled`, `readOnlyOnly`) use `extractExtensionSettings`, which never copies meta/icons, so a bad meta fails only its own tool
