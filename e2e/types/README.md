# Compile-time type tests

These `*.types.ts` files check the public OpenAPI types the way a consumer sees them: they import from `'mcp-from-openapi'`, are compiled by `yarn typecheck` and are never executed. Jest ignores them, because their names end in neither `.e2e.ts` nor `.spec.ts`.
`documents`, `reads` (including `toJsonSchema` of a boolean schema), `methods` (HTTP methods, declared versions, the Swagger 2.0 family, diagnostics, the `documentUri` load option), `tools` (a generated tool and the request built from it: mapper entries, response streams, response status codes and ranges, server names), `extensions` and `fixtures` (real documents imported as JSON modules) hold code that must keep compiling. `swagger2` holds everything about Swagger 2.0 in one place: the `OAS20` namespace (a realistic Swagger 2.0 document, how it is read, its required and per-version keys as assertions, what the cross-version aliases (`OpenAPIDocument`, ...) say about it: they are not 2.0 types), the conversion as a function (`upgradeSwagger2`, its options and result, the two bounds, the `document` marker of a diagnostic, which says which document of a 2.0 document its `path` is into), and its own rejections. `shapes` states required keys, per-version keys and field types as type-level assertions (`Expect<Equal<...>>`), among them the exact set of the `SWAGGER_*` diagnostic codes and the shape of the options and result of `upgradeSwagger2`. `rejections` (and the end of `extensions`) holds code that must not compile, each case marked `// @ts-expect-error`; an unused directive is itself a compile error.
To add a case, put it in the file for its kind and run `yarn typecheck`, then break the case once to see it fail. Give every `@ts-expect-error` exactly one reason to fail (a literal with a second error, such as an extra field next to a missing one, keeps passing when the first is fixed); state required-ness in `shapes`, where nothing can mask it.
